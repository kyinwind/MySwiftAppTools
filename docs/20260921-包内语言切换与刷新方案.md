## 一、问题

### 1.1 现象（杨哥反馈）

在 RightClickMate 设置里切换 App 语言，**消息历史界面的文案不跟着变**（仍是切换前的语言），App 自己的界面刷新正常。

### 1.2 根因：两条都缺

`packageL` 现在的实现（`Localization.swift:19-26`）：

```swift
public func packageL(_ key: String, _ args: CVarArg...) -> String {
    localizedFormat(key, bundle: .module, arguments: args)
}

private func localizedFormat(_ key: String, bundle: Bundle, arguments: [CVarArg]) -> String {
    let format = bundle.localizedString(forKey: key, value: nil, table: nil)
    return String(format: format, locale: .autoupdatingCurrent, arguments: arguments)
}
```

**缺失一：没有定向到指定语言的 `.lproj`。**
`Bundle.localizedString` 用的是 bundle 的「首选本地化」，它由 `AppleLanguages` 在**进程启动时解析并缓存**。App 内改语言（改 UserDefaults）不会让 Foundation 重新解析，所以 `Bundle.module` 一直吐旧语言。

**缺失二：SwiftUI 没有任何可观察的状态变化。**
即使字符串变了，视图也不会重绘 —— `packageL` 是普通全局函数，读的不是任何 `@Observable` 属性。

### 1.3 对照：`SwiftHelpCenter` 已经解决了（同作者，可照抄机制）

`SwiftHelpCenter 0.2.1` 的 `AppLanguageManager.swift` 做了两件事：

1. **定向查表**：显式构造目标语言的 lproj Bundle，绕开启动期缓存
   ```swift
   if let path = sourceBundle.path(forResource: resourceName, ofType: "lproj"),
      let localizedBundle = Bundle(path: path) {
       return localizedBundle.localizedString(forKey: key, value: nil, table: tableName)
   }
   ```
   并且有**三级回退**：lproj Bundle → 直接读 `\(name).lproj/Localizable.strings` → 标准查表。第二级是专门应对 SPM / Preview 下 lproj 不可达的。

2. **强制重建视图树**：`SHCAppLanguageManager`（`@MainActor @Observable`）在 `selection` 变化时 `refreshToken = UUID()`，再由
   ```swift
   func SHCAppLanguage(_ manager: ... = .shared) -> some View {
       environment(\.locale, manager.locale).id(manager.refreshToken)
   }
   ```
   用 `.id(...)` 把整棵子树换掉。

**结论**：SHC 的界面能刷新，靠的就是这两条；`MySwiftAppTools` 两条都没有。所以这不是「SwiftUI 不自动刷新」的锅，是包没搭这套管线。

## 二、方案设计

### 2.0 先排除两个方向

| 方向 | 否决理由 |
|---|---|
| 让 `MySwiftAppTools` 依赖 `SwiftHelpCenter` 复用 | 基础包会被绑上 HelpCenter / Feedback / ReviewPrompt / AppStoreHelper 一整坨，还引入 `EasyDesignSystem` 传递依赖。**基础包不该为改个语言背这些。** （已确认 SHC 只依赖 EasyDesignSystem、不反向依赖本包，所以技术可行，是**不该**而非**不能**） |
| 只给 `ToastHistoryView` 打补丁 | 治标。`ThemeManager` / `PermissionManager` 的文案照样不刷新，下次换个界面又要再修一遍 |

### 2.1 三层结构（机制与 SHC 对齐，实现独立）

**第一层：查表 —— `PackageLocalization`（`nonisolated`，供 `packageL` 调用）**

```swift
public enum PackageLocalization {
    /// 当前生效的 lproj 资源名（如 "zh-Hans" / "en"）。nil = 走 Bundle.module 默认解析（即现状，跟随系统）。
    nonisolated(unsafe) public static var resourceName: String?

    static func localizedFormat(_ key: String, arguments: [CVarArg]) -> String
}
```

查找策略（三级回退，与 SHC 一致）：

1. 按 `resourceName` 定位 `Bundle.module` 内的 lproj → `Bundle(path:)` → 查表
2. 直接读 `\(resourceName).lproj/Localizable.strings` 成字典 → 取 key（兜底 SPM / Preview 下 lproj 不可达）
3. 回退 `Bundle.module.localizedString(...)`（= 现有行为）

> **大小写坑**：SHC 传出来的资源名是小写 `"zh-hans"`，而本包目录名是 `zh-Hans.lproj`。macOS 默认文件系统大小写不敏感，能命中；但不能赌。实现要在 `Bundle.module.localizations`（返回真实目录名）里做**大小写不敏感匹配**，匹配不到再落回原字符串。

**第二层：状态 —— `PackageLanguageManager`（`@MainActor @Observable`）**

```swift
@MainActor
@Observable
public final class PackageLanguageManager {
    public static let shared = PackageLanguageManager()

    public private(set) var language: PackageLanguage
    /// 语言变化时更新，供 SwiftUI 用 .id(...) 强制重建。
    public private(set) var refreshToken: UUID

    public func setLanguage(_ language: PackageLanguage)
    public func followSystem()
    /// 不改语言，只触发一次重绘（外部改了 Bundle 之外的资源时用）。
    public func refresh()
}

public enum PackageLanguage: Sendable, Equatable {
    case system                 // 跟随系统（默认）
    case zhHans
    case english
    case custom(String)         // 任意 lproj 资源名，便于对接外部语言系统
}
```

`custom(_)` 是关键：RightClickMate（以及后续 TTSMate / 视频类 App）用的是 SHC 的 `SHCAppLanguagePreference`，包**不能** import 它。好在拍板的「modifier 传值」形态正好适配 —— 把它的资源名原样传进去即可（SHC 给的是小写 `"zh-hans"`，包内做大小写不敏感匹配）：

```swift
// 推荐：根视图套一次，值变即自动同步 + 重建
RootView()
    .packageLanguageRefresh(resourceName: SHCAppLanguageManager.shared.selection.resourceName)
```

命令式切换也可以：

```swift
PackageLanguageManager.shared.setLanguage(.english)
PackageLanguageManager.shared.setResourceName("en")   // 对接外部语言系统
PackageLanguageManager.shared.setResourceName(nil)    // 回到「跟随系统」的默认解析
```

**第三层：刷新 —— 两条路都给**

```swift
public extension View {
    /// 套在根视图上：语言切换时重建整棵子树。
    /// 建议每个 Window / Scene 的根视图都套一次。
    func packageLanguageRefresh(_ manager: PackageLanguageManager = .shared) -> some View {
        id(manager.refreshToken)
    }

    /// 跟随一个外部语言值自动刷新（拍板的推荐形态）。
    func packageLanguageRefresh(resourceName: String?) -> some View {
        modifier(PackageLanguageRefreshModifier(resourceName: resourceName))
    }
}
```

同时 **`ToastHistoryView` 内部自带观察**：它自己读 `PackageLanguageManager.shared.refreshToken`，语言一变就重建。这样独立窗口 / sheet 场景**零配置就能刷新**，调用方一行都不用写。

### 2.2 默认行为不变

`resourceName = nil`（默认）时，第 1、2 级都不命中，走第 3 级 `Bundle.module.localizedString` —— 与现在的 `packageL` 完全等价。**不接新 API 的 App，行为一字不差。**

### 2.3 明确不做

- 不自动监听 UserDefaults / `AppleLanguages` 变化（见 D3）
- 不改 `L(_:)`（那是 App 自己 bundle 的入口，归 SHC 管，两套不重叠）
- 不引入 iOS 支持（`Package.swift` 目前只声明 `.macOS(.v14)`，`ToastHistoryView` 里的 `#if os(iOS)` 分支实际编译不到）

| 编号 | 决策项 | 结论（均按推荐项拍板） |
|---|---|---|
| D1 | 语言枚举形态 | **`.system` / `.zhHans` / `.english` / `.custom(String)`** 四态。`.custom` 承载外部语言系统传来的资源名（含 `zh-hans` vs `zh-Hans` 的大小写差异），也是以后加日文的入口 |

## 七、0.1.71 修复：改为环境优先（2026-09-21）

### 7.1 0.1.70 的方案在 RightClickMate 上没生效

现象：设置里切英文后，消息历史仍显示中文。调用方按方案接了桥接：

```swift
.SHCAppLanguage(languageManager)
.onChange(of: languageManager.selection, initial: true) { _, new in
    PackageLanguageManager.shared.setResourceName(new.resourceName)
}
```

### 7.2 根因：全局值是「弱一致」状态

`PackageLanguageManager.resourceName` 是一个全局变量，靠**调用方每次语言变化都记得同步**来保持正确。这条链上任意一环断了，它就会停在旧值上：

- `.SHCAppLanguage(...)` 内部是 `environment(\.locale, …).id(refreshToken)` ——
  `.id()` 变化会**重建子树**，`onChange` 挂在外层，其「上一次的值」能否保留取决于重建时序；
- 一旦某次同步漏掉，全局值就永久停在旧语言，而且**它排在优先级更高位时，会把本来正确的路径遮蔽掉**。

对比之下，SHC 自己界面能刷新，靠的是 `environment(\.locale)` + `.id()` —— **全程声明式，没有一处依赖回调时序**。

### 7.3 修复：视图直接读环境 `Locale`

`ToastHistoryView` 新增 `@Environment(\.locale)`，语言优先级改为：

| 优先级 | 来源 | 一致性 |
|---|---|---|
| 1 | 环境键 `\.packageLanguageResourceName`（`.packageLanguageRefresh` / 独立窗口 wrapper 注入） | 强（SwiftUI 传播） |
| 2 | **环境 `Locale` 派生** —— SHC 的 `.SHCAppLanguage(...)` 注入的就是它 | **强（SwiftUI 传播）** |
| 3 | 全局值 `setResourceName(_:)` | 弱（靠调用方同步） |
| 4 | `nil` → `Bundle.module` 默认解析（跟随系统） | — |

**第 2 条排在全局值之前是这次修复的关键**：强一致的来源先赢，界面就不会被过期的全局值钉死。

于是调用方**不需要再写任何桥接代码** —— 只要用了 `SwiftHelpCenter` 的语言 modifier，包内界面就自动跟随，因为：

```
selection 变化 → SHC refreshToken 变化 → .id() 重建子树
              → 新子树带 environment(\.locale, Locale("en"))
              → ToastHistoryView 重新求值 → 读到 en → 查 en.lproj
```

全程是 SwiftUI 的声明式传播，**不存在「回调有没有被调用」这个不确定性**。

### 7.4 两种形态各自的取语言路径

| 形态 | 环境 `Locale` 来源 | 走哪条 |
|---|---|---|
| 嵌在 App 视图树里（sheet / 设置页） | SHC 注入（或系统值） | 优先级 2 —— **零桥接** |
| 独立窗口 `ToastHistoryWindowController` | 拿不到 App 的环境，只有系统值 | 优先级 1 —— 新的 `ToastHistoryWindowRoot` 把全局值注入环境键并观察语言变化 |

### 7.5 调用方迁移

- **嵌入形态**：删掉手写的 `onChange` + `setResourceName` 即可，自动跟随。
  想显式控制就用一行 `.packageLanguageRefresh(resourceName: languageManager.selection.resourceName)`。
- **独立窗口**：保持调 `setResourceName`（或 `.packageLanguageRefresh(resourceName:)`），
  窗口由 `ToastHistoryWindowRoot` 跟随。

### 7.6 新增 API

```swift
// 子树级语言注入键；包内视图读它取当前语言
EnvironmentValues.packageLanguageResourceName

// 指定 .lproj 资源名的查表（带 label + 数组参数，与可变参数版本不歧义）
packageL(_ key: String, resourceName: String?, arguments: [CVarArg]) -> String

// 由 Locale 推导资源名：候选从最具体试到最宽松
//   zh-Hans_CN → ["zh-Hans_CN", "zh-Hans-CN", "zh-Hans", "zh"]
// 再在 Bundle.module.localizations 里做大小写不敏感匹配；匹配不到返回 nil
PackageLocalization.resourceName(for: Locale) -> String?
```
