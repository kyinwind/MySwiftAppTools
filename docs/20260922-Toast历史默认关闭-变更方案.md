# Toast 消息历史默认关闭 —— 变更方案

- 文档日期：2026-09-22
- 涉及模块：`Sources/MySwiftAppTools/Toast/ToastHistoryStore.swift`、`ToastManager.swift`
- 目标版本：**0.1.72**
- 状态：**已实施完成（2026-09-22）** —— `swift build` / `swift test` 全绿（55 tests, 0 failures）

---

## 一、需求

杨哥原话：

> 要改默认，如果用户不显式调用 `ToastManager.shared.configureToastHistory` 并且指定 `isHistoryEnabled = true`，我们不应该就默认记录消息历史。

即：**消息历史的默认状态由「开」改为「关」**，必须显式开启。

### 为什么这个需求是对的

现状是「不配置即默认写盘」—— 一个 App 只想用 Toast 弹个提示，却**被动**开始往 UserDefaults 写历史数据。这是三种问题叠在一起：

1. **隐私**：toast 文本常含用户文件路径（RightClickMate 就天天弹 `已处理 /Users/xxx/…`），默认落盘等于默认收集。
2. **不可见**：调用方没写任何相关代码，却产生了持久化写入，排查时想不到是这里。
3. **不可逆**：旧版本升级后自动开始写，用户无从知情。

「默认关、显式开」是这类有副作用的持久化功能应有的默认姿态。

## 二、影响面调研（已实测）

### 2.1 包内引用点

| 文件 | 行 | 内容 | 处理 |
|---|---|---|---|

| `ToastHistoryStore.swift` | 143 | `self.isHistoryEnabled = isHistoryEnabled` | 不变 |

`configureToastHistory(...)` 本身**不需要改**：它的参数是 `Bool? = nil`，nil 表示「保持原值」，而原值现在默认是 `false` —— 语义自动正确。这也印证了当初「局部更新语义」的设计是对的。

### 2.2 已接入的 App（关键结论）

| App | 调用位置 | 是否显式开启 |
|---|---|---|
| RightClickMate | `RightClickMateApp.swift:92-94` | ✅ `isHistoryEnabled: true` |
| VideoHero | `VideoHeroApp.swift:159-161` | ✅ `isHistoryEnabled: true` |

**两个 App 都已显式写了 `isHistoryEnabled: true`，本次改动对它们零影响**，行为完全不变。这是本次改动敢于直接改默认值的前提。

### 2.3 测试影响（12 处会红）

`ToastHistoryTests.swift` 里 13 处 `store.configure(...)`，其中 **12 处**依赖旧的 `true` 默认值：

| 行 | 现写法 | 受影响原因 |
|---|---|---|
| 41 | `configure(maxCount: 100, excludedTypes: [])` | 不传开关 → 改后为 false |
| 56 | `configure(excludedTypes: [])` | 同上 |
| 76 | `configure(maxCount: 3, excludedTypes: [])` | 同上 |
| 88 | `configure(excludedTypes: [], maxMessageLength: 10)` | 同上 |
| 100 | `configure(maxCount: 100, excludedTypes: [], maxTotalBytes: 512)` | 同上 |
| **115** | `configure()` | **纯默认调用**，`testLoadingExcludedByDefault` 整条会失败 |
| 125 | `configure(excludedTypes: [])` | 同上 |
| 146 / 159 / 171 | `configure(excludedTypes: [])` | 删除相关用例，record 不到东西 |
| 210 / 214 | `configure(excludedTypes: [])` | App Group 双实例用例 |

根因：`ToastHistoryStore.configure(...)` 是**全量重置**语义（未传参数回落默认值），所以它不看 `setUp` 里对共享单例设的 `true`。

## 三、改动方案

### 3.1 源码：2 行

```swift
// ToastHistoryStore.swift:101
public internal(set) var isHistoryEnabled = false      // was: true

// ToastHistoryStore.swift:136
isHistoryEnabled: Bool = false,                        // was: true
```

### 3.2 测试：12 处补显式参数 + 1 条新用例

受影响用例一律补 `isHistoryEnabled: true`（保留原测试意图，不改变断言）。

新增一条守住新默认：

```swift
func testHistoryDisabledByDefault() {
    let store = ToastHistoryStore()
    store.configure(excludedTypes: [])            // 不传开关
    store.record(message: "不该被记录")
    XCTAssertTrue(store.records.isEmpty, "未显式开启时不应记录任何历史")
}
```

同时把 `ToastManager` 那条链也守住（这才是调用方真正走的路径）：

```swift
func testConfigureToastHistoryDoesNotEnableByDefault() {
    // 只改条数，历史应保持关闭
    ToastManager.shared.configureToastHistory(maxCount: 100)
    XCTAssertFalse(ToastManager.shared.toastHistory.isHistoryEnabled)
}
```

### 3.3 文档同步

- `README.md`：把「默认即开箱可用」的描述改为「默认关闭，需显式开启」，示例代码保留显式 `isHistoryEnabled: true`（正好成为正确示范）；第 579 行的隐私提示同步改写。
- `CHANGELOG.md`：新版本段里用 **行为变更** 标注，说明「升级后若未显式开启，不再写入历史；已开启的 App 不受影响」。
- `docs/20260920-Toast消息历史与浏览界面-方案设计.md`：第 79 行与 483 行记录了旧决策（默认开启 + release note 要提醒关闭），加一段「变更说明」指向本文档，避免以后翻旧文档被误导。

### 3.4 不做的事

- **不清理已有历史数据**。改默认只管「以后还记不记」，plist 里的旧记录保留，用户可以在界面上看和删。擅自删用户数据更糟。
- **不改 `excludedTypes` 默认值**（仍是 `[.loading]`）。显式开启的人多半也想排除 `loading`。
- **不给 `configureToastHistory` 加「调用了就算开启」的隐式魔法**。那会让「只改条数」意外打开记录，比现在更难排查。

- **视图**：`emptyState` 按 `store.isHistoryEnabled` 分叉图标与文案；新增 `ToastHistoryPreviewData.makeDisabledStore()` 与 Preview `"消息历史 · 历史未开启"`。
- **文案**：`Toast.History.disabled` / `Toast.History.disabledHint`（zh-Hans + en 同步）。
- **验证**：`swift build` 通过；`swift test` **55 tests, 0 failures**（53 → 55）。
- **文档**：README（快速开始 + 消息历史章节 + 隐私说明）、`CHANGELOG.md`（0.1.72 段）、`20260920` 旧方案文档加文首批注。
- **未做**：不清理既有历史数据（只改「以后记不记」）；不改 `excludedTypes` 默认值；不给 `configureToastHistory` 加「调用了就算开启」的隐式魔法。

### 踩到的坑（留档）

1. **参数顺序**：`configure` / `configureToastHistory` 的形参顺序是
   `maxCount:isHistoryEnabled:excludedTypes:maxMessageLength:maxTotalBytes:deferredPersist:`，
   补参数时必须把 `isHistoryEnabled` 插在 `maxCount` **之后**，写成
   `configure(isHistoryEnabled: false, maxCount: 500)` 会编译失败（`argument 'maxCount' must precede argument 'isHistoryEnabled'`）。
2. **`PublicAPITests` 的失败恰好证明了改动生效**：它原先 `ToastHistoryStore()` 新建实例后直接
   `record` 并断言有 1 条，依赖的正是旧的 `true` 默认值 —— 一改成 `false` 就立刻红了。
