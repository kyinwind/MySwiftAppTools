## 一、需求分析

### 1.1 原始诉求（杨哥原话拆解）

| 编号 | 诉求 | 我的理解 |
|---|---|---|
| R1 | 包里应该给窗口设置好背景色 | 库视图要「开箱即有底」，不能把背景责任推给调用方——调用方漏加就是一片透明绣花 |
| R2 | 否则其他 App 使用会搞成透明 | 这是真实缺陷。RightClickMate 已经踩到（`MainView.swift` 的 `.toastHistory` 分支） |

出自 RightClickMate 的实际落点（`RightClickMate/View/MainView.swift:252`）：

```swift
case .toastHistory:
    ToastHistoryView()
        .frame(maxWidth: .infinity, maxHeight: .infinity)
        .background(EDSTheme.shared.colors.pageBackground)
```

### 1.2 实测取证：先纠正一处口径

**「独立窗口透明」不成立。** 探针工程 `/tmp/BGProbe` 直接调 `ToastHistoryWindowController.shared.show()`，抓窗口属性 + 抓图：

| 形态 | `window.isOpaque` | `window.backgroundColor` | `NSHostingView.isOpaque` | `layer.backgroundColor` | 实际观感 |
|---|---|---|---|---|---|
| A. 独立窗口（包内 controller） | `true` | `System windowBackgroundColor` | `false` | `nil` | **浅灰实底，正常** |
| B. 裸嵌入（`ZStack { Color.orange; ToastHistoryView() }`） | `true` | `System windowBackgroundColor` | `false` | `nil` | **整片透出橙色** |

截图证据：`bgprobe_A.png`（独立窗口，浅灰实底）、`bgprobe_B.png`（嵌入，全屏橙色透出，连 header 都是橙的）。

**结论**：真正缺底的场景是 **B —— 把 `ToastHistoryView` 裸嵌进别人的容器**。独立窗口只是「借」了窗口自己的底，看起来正常，属于**偶然正确**，不是包主动保证的。

### 1.3 根因

`ToastHistoryView` 的 `body`（第 59–93 行）只有 `VStack { header; Divider; listArea }` + `.frame(...)`，**全程没有任何一层 `.background(...)`**。

SwiftUI 视图不画背景即透传，于是：

- 放在 `NSWindow` / `.sheet` 里 → 露出窗口或 sheet 面板自带的底，看着正常；
- 裸嵌进别人的 `ZStack` / `VStack` → 露出宿主容器的底，出事故；
- 若宿主是**透明窗口**（`isOpaque = false`，做无边框浮窗的 App 常见）→ 直接露出桌面。

即：**当前能正常显示，靠的是宿主恰好有底，而不是包自己兜住。** 这是设计缺陷，不是配置问题。

### 1.4 明确不做（本次范围外）

- 不改 `ToastManager` 的 toast 浮层（它自己 `.background(item.type.backgroundColor)` 已有底，`ToastManager.swift:396`）
- 不给 `ToastHistoryView` 接 `ThemeManager`（理由见 2.3）
- 不做「跟随系统壁纸」的 vibrancy 毛玻璃（无真实需求，YAGNI）

## 二、方案设计

### 2.1 视图层：新增背景选项（本次核心）

给 `ToastHistoryView.init` 增加第 5 个参数，**带默认值，老调用方源码零改动**：

```swift
/// 历史界面的背景样式。
public enum ToastHistoryBackground: Sendable {
    /// 不画背景，完全由调用方接管（外层 `.background(...)` 可正常生效）
    case none
    /// 系统语义背景（默认）：浅色/深色自动适配，与窗口、sheet 底色一致
    case system
    /// 指定颜色，供调用方注入自家主题色
    case color(Color)
}
```

```swift
public init(
    store: ToastHistoryStore = .shared,
    pageSize: Int = 20,
    showsClearAllButton: Bool = true,
    onClose: (() -> Void)? = nil,
    background: ToastHistoryBackground = .system   // 新增，放最后
)
```

实现落在 `body` 上，与既有 `.transaction` 并列：

```swift
.transaction { $0.animation = nil }
.frame(minWidth: 360, minHeight: 280)
.background(backgroundStyle)        // 新增：包自己兜底
```

解析规则：

| case | macOS | iOS |
|---|---|---|
| `.none` | `Color.clear`（不铺底） | 同左 |
| `.system` | `Color(nsColor: .windowBackgroundColor)` | `Color(uiColor: .systemBackground)` |
| `.color(c)` | `c` | `c` |

粒度：**只铺在根视图一层**，不给 header / footer / 行单独铺底。这样 `.background(.bar)`（分组吸顶，第 225 行）和 `Color.primary.opacity(0.05)`（行悬浮，第 366 行）的层次关系保持原样。

### 2.2 窗口层：显式兜底（防御性，一行）

`ToastHistoryWindowController` 目前只是**碰巧**有底。显式写死，防未来改 `styleMask` 或加 `titlebarAppearsTransparent` 时失手：

```swift
window.backgroundColor = .windowBackgroundColor
window.isOpaque = true
```

同时 `show(...)` 增加 `background: ToastHistoryBackground = .system` 参数，透传给 `ToastHistoryView`，让独立窗口也能被调用方换色。

### 2.3 为什么不接包内 `ThemeManager`

包里已有 `ThemeManager.theme.myBGColor`（默认 `Color.myGray`），理论上可以让历史界面跟随。**但不做**：

1. `ToastHistoryView` 目前对 `ThemeManager` **零依赖**（不需要 `@Environment(ThemeManager.self)`）。一旦默认取它，未注入 environment 的 App 会**直接崩**——把「可选增强」变成「必需依赖」，属于倒退。
2. `ThemeManager` 是套餐式主题（`ThemeColors` 一整组），给一个日志列表页套整套主题，耦合过重。
3. `.color(_)` 已经覆盖了这个需求：想跟主题走的调用方传 `ToastHistoryView(background: .color(ThemeManager.shared.theme.myBGColor))` 即可，**一行，且意图明确**。

### 2.4 关键副作用（必须知道）

**包内加底会盖住调用方写在「视图实例外层」的背景。**

```swift
ToastHistoryView().background(EDSTheme.shared.colors.pageBackground)
```

这行的背景画在**最底层**，包内 `.background(.system)` 画在它**上面**，于是 EDSTheme 完全失效。

→ 所以 RightClickMate 那两行**必须改写**（迁移见 3.2）。这也是我把 `.color(_)` 放进 enum 的原因：给它一个正确的接管姿势。

## 三、影响面与迁移

### 3.1 兼容性

| 维度 | 结论 |
|---|---|
| 源兼容 | ✅ 新参数有默认值，老调用方不改一行即可编译通过 |
| 行为变化 | ⚠️ 默认多一层系统底；调用方若在外层自加背景，会被盖住（见 2.4） |
| 独立窗口 | ✅ 观感无变化（本来就有底），行为更稳 |
| `.sheet` 场景 | ✅ 系统语义色与 sheet 面板底色一致，无接缝 |
| 破坏性 | ❌ 无，进 `0.1.x` |

### 3.2 RightClickMate 迁移（改完后要做）

```swift
// 改前
ToastHistoryView()
    .frame(maxWidth: .infinity, maxHeight: .infinity)
    .background(EDSTheme.shared.colors.pageBackground)

// 改后（二选一）
// 方案 a：跟随 EDSTheme 主题色 —— 推荐，保持视觉一致
ToastHistoryView(background: .color(EDSTheme.shared.colors.pageBackground))
    .frame(maxWidth: .infinity, maxHeight: .infinity)

// 方案 b：用包的系统底，删掉自定义背景
ToastHistoryView()
    .frame(maxWidth: .infinity, maxHeight: .infinity)
```

### 3.3 其他已接入方

`VideoHero` 只用 `ToastHistoryWindowController`（独立窗口形态），**不受影响**，无需改动。

   - `.none` → 应透出橙色（预期行为，调用方自己接管的场景）

4. **回归**：`swift build` + `swift test` 全绿；老调用形式（不传新参）编译通过。
